#### Subtask 1.4 - COMPLETED
**Goal:** Investigate whether a local LLM icon exists or can be created following the same icon + status + popover pattern

**Findings:**

**1. OllamaIcon already exists**

- **File:** `apps/frontend-web/src/components/icons/OllamaIcon.tsx`
- **Interface:** `{ className?: string }` — identical to `AnthropicIcon`, `OpenAIIcon`, `GeminiIcon`
- **SVG:** Circular Ollama logo (llama head silhouette) rendered with `fill="currentColor"`, inherits text color
- **Export:** Named export `OllamaIcon` — ready to import and use immediately

**2. Backend detection endpoint already exists**

- **Endpoint:** `GET /settings/local-llm/detect` in `apps/web-server/server/routes/settings.py` (line 489)
- **Detection method:** Uses `shutil.which("ollama")` (binary check) + `ollama --version` + `pgrep -x ollama` + `ollama list` — no HTTP probing
- **Response shape:**
  ```json
  {
    "providers": [
      {
        "id": "ollama",
        "name": "Ollama",
        "url": "http://localhost:11434",
        "detected": true,
        "installed": true,
        "running": true,
        "version": "0.14.3",
        "modelCount": 3,
        "models": ["llama3.2:latest", "qwen2.5:7b", "mistral:latest"]
      }
    ]
  }
  ```
- **Status semantics:** `running=true` → actively serving, `installed=true && running=false` → installed but stopped, `installed=false` → not found

**3. LocalLLMSettings already uses OllamaIcon + apiRequest pattern**

- **File:** `apps/frontend-web/src/components/settings/sections/LocalLLMSettings.tsx`
- Imports `OllamaIcon` and calls `/settings/local-llm/detect` via `apiRequest()` — exactly the data-fetching pattern needed
- Defines a local `LLMProvider` interface (`{ id, name, url, detected, installed, running, version, modelCount, models }`)

**4. Feasibility: FULLY FEASIBLE — recommended to implement in subtask 2.4**

A new `LocalLLMStatusBadge.tsx` (or `OllamaStatusBadge.tsx`) component can be created following the same icon + status dot + tooltip + popover pattern:

**Status dot mapping (analogous to CLI tools):**
- `running=true` → `bg-green-500` (active, serving models)
- `installed=true, running=false` → `bg-yellow-500` (installed but not running)
- `installed=false` → `bg-muted-foreground/40` (not installed)

**Trigger button (header, iconOnly):**
```tsx
<Button variant="ghost" size="icon" className="h-8 w-8">
  <div className="relative">
    <OllamaIcon className="h-4 w-4" />
    <span className="absolute -bottom-0.5 -right-0.5 h-2 w-2 rounded-full {dotColor}" />
  </div>
</Button>
```

**Popover content:** Version, model count, list of detected models, install hint if not installed.

**Key differences vs Codex/Gemini badges:**
- No auth/login concept — status is purely `running` + `modelCount`
- Uses `apiRequest('/settings/local-llm/detect')` (REST) instead of `window.API.detectCLIAccounts` (IPC)
- No `CLIAccountStatus` type needed — can use a local `OllamaStatus` interface
- Popover actions: only "Refresh" + link to ollama.ai if not installed (no Install button since Ollama is a desktop app)

**5. New type needed (no existing type covers Ollama status):**

`CLIAccountStatus` is typed as `cli: 'codex' | 'gemini'` and includes auth/token fields not applicable to Ollama.
A new local interface (defined in the new component file) is the cleanest approach:
```ts
interface OllamaStatus {
  installed: boolean;
  running: boolean;
  version: string;
  modelCount: number;
  models: string[];
}
```
